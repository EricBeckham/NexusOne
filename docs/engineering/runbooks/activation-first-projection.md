# 首次开通时权益投影不存在

现场断点（2026-09-28）：Demo Acme 租户 `01900000-0000-7000-8000-000000000101` 的权益投影无行，平台批准待办开通申请 `d0a24adb-8891-4050-b205-d4e34c1353aa` 时得到 `optimistic lock failed for entitlement projection ...0101`，事务回滚。申请保持 PENDING，订阅和安装均未落库。不要在演示库手工插投影、修改申请状态或重复创建已保存的「Cursor自动化」目录数据。

修复：P4 在事务内读取目标租户投影；无行时通过 P1 仓储专用首次 INSERT 写入版本 1，有行时继续以 `version = previous_version` 更新。首次 INSERT 对 `tenant_id` 主键用 `ON CONFLICT DO NOTHING`，若另一事务已先插入则抛乐观锁冲突，**不会覆盖**对方投影，也不会把当前审批标为通过。没有 Flyway、无权限或身份变更。

回归：`PlatformActivationPersistenceIT` 使用显式的一次性本机 PostgreSQL 空库和真实 P1 JDBC 投影仓储，验证首次批准写入、既有版本推进、两个事务争抢首次写入只留首个结果、权限包失败时投影与订阅安装共同回滚、重复审批拒绝。测试以 mock 代替真实 IAM/权限包/审计，故不能当作线上完整闭环验收。

正规合入与部署后，只对原 PENDING 申请从界面重试一次平台批准；读回其状态、订阅、安装与投影，再由租户管理员查看已开通/配置流程，普通用户从 P3「可用应用」发起，审批人填写意见，申请人读取结果。办结后付款台账另按真实数据复验。未到达的节点一律记为未验证。

# DL-X3 · 演示机 remoke 纪律

> **预备 ≠ 验收。默认拒绝，不自动清理。** 本卡为 docs-only，不提供远程删除/重播脚本，也未在真机执行 remoke。

## 真机执行前的同时门禁

| 门禁 | 缺失处理 |
|---|---|
| 服务端 `NEXUS_DEMO_HOST_ALLOW=1`（精确值；请求头/客户端变量不代替服务端配置） | 拒绝；不开本地 demo seed 代替 |
| 具名操作者与已授权目标环境 | 拒绝匿名/共享身份；记录显示名，不记凭据 |
| 强平台管理员鉴权与受控短时确认令牌（若 API 要求） | 拒绝缺失/过期/错角色；令牌不入日志/仓库 |
| 操作者针对目标主机、租户、待清实体、保留项的**交互确认** | 未输入与操作单一致的确认、取消或无法交互一律拒绝；不使用 yes 管道/默认确认 |
| 备份/恢复方案、范围审阅、已合受控 API | 无证据停止；不即兴 SQL / 删除整个数据库 |

allow 只是许可门闩，不是授权，也不是单独的确认。所有条件同时满足后才由环境所有者执行已合受控清理；API 的确认令牌不能替代操作者对具体目标的交互确认。自动任务/CI 不得把缺失确认处理为成功。

## 操作单（填写脱敏事实，不代填）

1. 停止演示业务写入，记录发布SHA、目标环境与具名操作者、受控租户/实体范围。
2. 确认可恢复备份与保留项；共享租户、真实业务记录或范围不确定则 No-Go。
3. 环境所有者短时打开服务端 allow，核实管理员权限；向操作者展示目标与范围，得到明确交互确认。不打印确认令牌、Authorization、cookie、DB URL/口令。
4. 使用经过审核的 [DL-L2 受控 API](../../planning/WEB上线演示任务卡_DL波_V0.1.md)；使用前核实实现已合入与实际契约，规划不是可调用 API。不猜URI/请求体；接口不存在时记卡点停止。
5. 读回保留内容、待清范围和审计结果；失败留脱敏类别，不自动重试删除。
6. 关闭短时 allow/回收令牌，按 [Prod-safe 内容手册](demo-host-prod-safe-content.md) 准备与重跑；升级步骤不因此标DONE。

## 本地 reset 的不可跨越边界

[`scripts/demo/reset.ps1`](../../../scripts/demo/reset.ps1) 仅串行调用本地 clean 脚本；现有 clean-approval / clean-p1…p5 守卫只接受 PostgreSQL loopback（127.0.0.1、localhost、[::1]）、本地demo开关及非prod环境。本卡不改这些脚本、不扩大网络面。

真机即使通过隧道呈现 loopback，也不能据此用 reset：判断真实目标与环境，而非把转发地址当安全授权。禁止端口转发/改DB URL/强开demo flags绕过守卫。reset 是本地种子工具，不是 prod-safe remoke API。

回指：[真机 runbook](demo-host-realhost-launch.md)、[M7](../../planning/M7-Keycloak演示验收清单.md)。仅文档审阅，无包装脚本，因此没有“缺allow exit码”执行测试；实际API门闩测试归DL-L2。

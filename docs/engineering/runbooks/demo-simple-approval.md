# 请假报销产品演示 Runbook

本 Runbook 用于本机 / 内测演示 K20 的「演示数据 · 请假报销」产品：订阅开通 → 发起申请 → 审批人填写意见并同意或驳回 → 发起人在「我的申请」查看结果。

> **禁止连生产 / 默认关闭。** 全程只允许回环地址数据库（`127.0.0.1`、`localhost` 或 `[::1]`）。页面中的「演示数据」不是生产数据。不要把 `demo` profile 或演示开关写进正式启动配置。

## 1. 演示前准备

### 基础服务

- 本机 PostgreSQL 已创建 `nexusone` 数据库，且当前账号可执行 Flyway 迁移。
- JDK、Maven、Node.js 与 npm 已安装。
- `8080`（后端）和 `5173`（Web）未被占用。
- 使用一次性或可随时重建的本机数据库。清理用 `scripts/demo/clean-approval.ps1` 或一键 `scripts/demo/reset.ps1`（先停后端）。`clean-p4.ps1` 只清原 P4 演示市场种子，不含请假报销产品。Flowable 部署若残留，重建本机库最干净。

### 演示角色

准备同一租户下两个可以真实登录并已建立租户上下文的账号：

| 角色 | 用途 | 要求 |
| --- | --- | --- |
| 发起人 A（种子：林晓） | 开通、发起、查看「我的申请」 | 能进入星市和星枢；TENANT_ADMIN；stub 主题 `demo-seed:p2:lin` |
| 审批人 B（种子：周然） | 接收待办、填写意见、同意或驳回 | 与 A 同租户；可被 PERSON 字段选中；stub 主题 `demo-seed:p2:zhou` |

演示种子中的「林晓 / 周然」只有组织读模型数据，邮箱是 `.invalid`，没有 Keycloak 凭据，不能把它们当成可登录账号。账号、口令或 token 由本机 IdP / 内测环境提供，不写入仓库。使用 stub IdP 时也必须确保 A、B 的 `sub` 已映射到同一租户 membership；仅在登录页生成 token 并不会自动获得种子租户身份。

## 2. 启动演示档

在仓库根目录打开 PowerShell。环境变量只在当前窗口设置：

```powershell
$env:NEXUS_DB_URL = "jdbc:postgresql://127.0.0.1:5432/nexusone"
$env:NEXUS_DB_USER = "postgres"
$env:NEXUS_DB_PASSWORD = "<本机数据库口令>"
. .\scripts\demo\enable.ps1
mvn -q -DskipTests package
java -jar nexus-bootstrap\target\nexus-bootstrap-0.1.0-SNAPSHOT.jar
```

`enable.ps1` 必须点源执行（开头有 `. `），否则后续 Java 进程收不到演示开关。也可以显式加 `--spring.profiles.active=demo`，但不要修改默认 profile。

启动应满足：

- 日志出现「演示开关已打开。禁止连生产。」；
- 后端监听 `http://127.0.0.1:8080`；
- 数据库地址不是回环地址、环境名是 `prod` / `production`，或数据库地址为空时，启动应被拒绝；
- K20 幂等写入「演示数据 · 请假报销」、版本 `1.0.0`、SKU「演示数据 · 标准」，并发布一级审批流程；它不会自动替任何租户订阅或开通。

另开一个位于同一仓库的 PowerShell 窗口启动 Web：

```powershell
cd web
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。Vite 会把 `/api` 代理到 `http://127.0.0.1:8080`；若后端端口不同，在启动 Web 前设置 `NEXUS_API_ORIGIN`。

## 3. 演示路径

建议使用两个独立浏览器 profile，分别保持 A、B 的会话。每次登录后确认页头显示目标租户上下文；若提示「没有 TenantContext」或「需要租户上下文」，先完成租户切换再继续。

### A. 订阅并发起

1. 以发起人 A 登录。
2. 打开「星市 → 应用目录」（`/p4/market`）。
3. 找到「演示数据 · 请假报销」；应看到已发布版本 `1.0.0` 和 SKU「演示数据 · 标准」。
4. 点击「订阅开通 演示数据 · 标准」。这是无支付、即时开通；成功后页面进入「我的已开通」（`/p4/installations`）。
5. 在对应安装记录点击「发起」。表单应显示必填的「事由」和「审批人」。
6. 填写事由并选择审批人 B，提交申请。成功后进入「待办 → 我的申请」（`/p3/todos?box=requests`）。
7. 新申请的状态应为「进行中」，意见显示「暂无」。记下业务单号，供 B 定位。

若目标租户已经订阅，跳过第 4 步，直接从「我的已开通」发起。重复订阅报冲突时不要换租户伪造一条新数据。

### B. 审批并填写意见

1. 切换到审批人 B 的浏览器 profile 并登录同一租户。
2. 打开「星枢 → 待办 → 我的待办」（`/p3/todos?box=inbox`）。
3. 按业务单号选中 A 的申请。
4. 在「意见」输入可辨识文本，例如「演示审批通过」，然后点击「同意」。若要演示驳回，输入原因后点击「驳回」。
5. 操作成功后，该项离开「我的待办」并可在「已办」查看；页面不应再显示“意见仅本页保存”之类文案。

### C. 查看结果

1. 回到发起人 A 的浏览器 profile。
2. 打开「星枢 → 待办 → 我的申请」，必要时切换一次标签触发刷新。
3. 选中原业务单号。
4. 同意路径应显示「通过」和 B 的意见；驳回路径应显示「驳回」和 B 的意见。无申请时页面应诚实显示「暂无」。

演示驳回与通过两个结果时，分别发起两张申请；已经办结的申请不要复用。

## 4. 快速排障

| 现象 | 检查 |
| --- | --- |
| 目录没有演示产品 | 确认后端是在打开演示开关后重启；日志无 DemoProfileGate 拒绝；数据库已完成迁移 |
| 「我的已开通」为空 | K20 不自动订阅；回到应用目录点击「订阅开通」；确认当前会话有 tenant context |
| 发起页显示「暂无」 | 安装必须绑定 K20 已发布的表单版本；确认所选安装属于 `demo_simple_approval` |
| 审批人下拉为空 | B 必须在同一租户有 PERSON / membership；种子人员本身没有登录凭据 |
| B 看不到待办 | 发起时选择的 PERSON 必须映射到 B 当前登录身份；同时确认 A、B 的 tenant context 相同 |
| A 一直看到「进行中」 | 先确认 B 已办结正确业务单号，再刷新「我的申请」；不要把「我发起」与「我的申请」混用 |
| 远程数据库启动失败 | 这是预期保护；改用本机回环数据库，不要绕过 DemoProfileGate |

## 5. 收尾

1. 停止 Web 和后端进程。
2. 若使用一次性本机数据库，删除并重建该数据库是当前清除 K20 数据的可靠方式。
3. 对其他 V-SEED 数据，如需保留数据库，按 [演示开关](../demo-profile.md) 的逆序清理说明执行；优先用 `reset.ps1` / `clean-approval.ps1`；不要把 `clean-p4.ps1` 当成请假报销产品全量清理。
4. 在启动后端的 PowerShell 中关闭演示开关：

   ```powershell
   . .\scripts\demo\cleanup.ps1
   ```

5. 再次启动普通 profile 时确认日志不再出现演示开关已打开，应用目录不会因关闭开关新增任何演示行。关闭开关不会自动删除已经写入的行。

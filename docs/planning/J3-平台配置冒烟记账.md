### 环境备注（非产品断点）

本机首次以后台方式启动 JAR 时，JDK 21 在 Windows 上创建 NIO 选择器的内部回环管道失败（`Unable to establish loopback connection` / `SocketException: Invalid argument: connect`，发生在 `HttpWebhookTransport` 构造 `HttpClient` 时）。用最小 Java 程序单独 `Selector.open()` 可稳定复现，与产品代码无关。为 JVM 加 `-Djdk.net.unixdomain.tmpdir=<worktree>\.local\tmp`（JDK 的 Unix-domain socket 目录）后正常启动。演示机若遇同样报错可用同一参数。

## 断点与观察（只记账，本卡不改代码）

- **断点 B（阻塞「用种子流程直接绑产品」，不阻塞本路径）**：空库启动后 `business_meta.process_definition_draft` 为 **0 行**，但 Flowable 已有 1 个 `demoSimpleApproval` 部署（租户 `…0101`）。K20 种子（`ApprovalProductDemoSeedConfiguration`，`@Order(100)`）插入流程草稿时 `SELECT … FROM platform.tenant WHERE id = 演示租户`，而演示租户由 P1 种子创建、P1 种子无 `@Order` 故在其后执行，首启时该租户尚不存在，草稿被跳过（种子幂等，二次启动预计会补上，本卡未验证）。产品定义页只把「有草稿且已发布」的流程列为可选，所以首启空库看不到种子流程；「流程设计器」却把它列为「已发布只读」（来自流程定义目录）。建议：修 K20 种子顺序（例如在种子内确保租户存在或调整执行顺序），或让产品定义页同时读取已发布流程目录。
- **观察 A（展示，非阻塞）**：未登录（仅平台操作头）时 `GET /api/v1/process/drafts` 返回 **401** `P2.IAM.UNAUTHORIZED`「missing bearer token」。I7 的可读提示只识别 403 / `TenantContext`，因此流程字段显示通用文案「流程列表暂时读不到（追踪号 …），可稍后刷新重试。」而非「需要租户身份」。上架步骤仍正确显示「需要租户身份才能读取」。建议把 401 也归入「需要登录租户身份」提示。

## 结论与收尾

J3 指定的 **新建模板 → 校验 → 发布 → 绑定产品** 在本机 demo 空库**通过**：I9 的审计 `tenant_id` 断点已由 I7 / J1 消除，新模板可保存、校验、发布，并出现在产品定义页的已发布模板下拉中；以新模板 + 新发布流程创建产品定义并绑定 SKU 成功，目录与库、审计三方复核一致。首启空库下种子流程不可直接选用（断点 B），本次通过 UI 新发布一个流程绕过，属真实可用路径而非伪造数据。此结论不覆盖真实 Keycloak、外网演示机或 `prod` profile。

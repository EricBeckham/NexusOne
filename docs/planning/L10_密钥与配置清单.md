# L10 密钥与配置清单（2026-09-25）

- 基线：`main@cbadfbc8`（含 L8 #401）
- 本文**只列名称、用途和注入方式，不含任何真实值**。真实值只放在部署环境的密钥管理处（环境变量注入或运维保管库），**禁止**提交到仓库、写进 `application*.yaml`，或贴到工单和聊天里。
- 产品配置源：`nexus-bootstrap/src/main/resources/application.yaml`（各库自带的 `application.yml` 不是单体的配置源）。本地示例：根目录 `.env.example`，值都留空。
- 平台密钥由 `SecretPort` 管理，产品 bean 是 `LocalThenEnvSecretPort.durableSystem`：先查本地加密存储 `platform.secret_ciphertext`，查不到再读进程环境变量。环境变量是**进程启动时的快照**，改了需要重启；写入本地存储的密钥可以不重启就轮换。

## 1. 平台级密钥（部署时注入）

| 环境变量 | 用途 | 读取方式 | 缺失 / 空值时 | 泄露影响 | 轮换 |
|---|---|---|---|---|---|
| `NEXUS_CRYPTO_MASTER_KEY` | 主密钥（hex），派生 AEAD 和 MAC 密钥，用来加密 `platform.secret_ciphertext` 中所有密文 | Spring `nexus.crypto.master-key`，**仅当** `NEXUS_CRYPTO_KEY_SOURCE=env` 时使用 | `key-source=env` 时启动失败；`ephemeral`（默认）时每次启动随机生成，**重启后所有持久化密文都读不出来**（见 L8 §3-A） | 所有托管密钥（IdP、P5 Credential）可被解密 | 换主密钥前要先把已有密文重新加密（目前没有自动迁移工具）。配套：`NEXUS_CRYPTO_KEY_ID`、`NEXUS_CRYPTO_KEY_VERSION`、`NEXUS_CRYPTO_SUITE` |
| `NEXUS_DB_PASSWORD` | 主库 Postgres 密码（配合 `NEXUS_DB_URL`、`NEXUS_DB_USER`） | Spring `spring.datasource.password` | 连库失败 | 整库数据 | 在数据库侧改密码后重启应用 |
| `NEXUS_IAM_JDBC_PASSWORD` | IAM 数据源的密码。**仅当** `NEXUS_IAM_PERSISTENCE=jdbc` 时使用（配合 `NEXUS_IAM_JDBC_URL`、`NEXUS_IAM_JDBC_USERNAME`） | `nexus.iam.jdbc.password`；L12 起默认等于 `spring.datasource.password`（复用主库） | 一般不需要单独设置 | IAM 表 | 同上 |
| `NEXUS_PERMISSION_JDBC_PASSWORD` | 权限数据源的密码。**仅当** `NEXUS_PERMISSION_PERSISTENCE=jdbc` 时使用（配合 `NEXUS_PERMISSION_JDBC_URL`、`NEXUS_PERMISSION_JDBC_USERNAME`） | `nexus.permission.jdbc.password`；L12 起默认复用主库 | 一般不需要单独设置 | `iam.perm_*` 表 | 同上 |
| `NEXUS_IAM_KEYCLOAK_CLIENT_SECRET` | 平台登录用的 Keycloak confidential client 密钥（配合 `NEXUS_IAM_KEYCLOAK_ISSUER`、`NEXUS_IAM_KEYCLOAK_CLIENT_ID`、`NEXUS_IAM_KEYCLOAK_REDIRECT_URI`）。**仅当** `NEXUS_IAM_IDP=keycloak` 时使用 | Spring 宽松绑定 `nexus.iam.keycloak.client-secret`，**不经过 SecretPort** | 登录换 token 失败 | 可冒充平台客户端向 IdP 换 token | 先在 Keycloak 轮换，再重启应用 |
| `NEXUS_PLATFORM_BOOTSTRAP_TOKEN`（别名 `NEXUS_IAM_PLATFORM_BOOTSTRAP_TOKEN`） | IAM 引导请求头令牌，用于首次初始化平台 | Spring `nexus.iam.platform-bootstrap-token`；`IdentityAuthFilter` 比对 | **空 = 关闭引导入口**（推荐：上线后保持为空） | 可调用引导接口 | 用完即清空并重启 |
| `NEXUS_FILE_BOOTSTRAP_TOKEN` | 文件 API 引导请求头令牌 | Spring `nexus.files.platform-bootstrap-token`；`FileIsolationFilter` 比对 | 空 = 关闭 | 可绕过租户上下文访问文件 API 的引导路径 | 同上 |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | MinIO/S3 对象存储凭据，配合 `S3_ENDPOINT` 和 `S3_TEST_BUCKET`（桶名）。**仅当** `NEXUS_FILE_STORAGE` 使用 S3/MinIO 时需要 | **SecretPort 环境适配器**（逻辑名 `s3.access-key` / `s3.secret-key`），不是 Spring 属性 | 对象存储不可用 | 桶内全部对象 | 在存储侧轮换后重启 |

**说明**：
- `SecretNames` 中还定义了逻辑名 `iam.keycloak.client-secret` → `NEXUS_KEYCLOAK_CLIENT_SECRET`、`datasource.password` → `NEXUS_DB_PASSWORD`、`crypto.master-key` → `NEXUS_CRYPTO_MASTER_KEY`、`iam.platform-bootstrap-token` → `NEXUS_PLATFORM_BOOTSTRAP_TOKEN`。但当前产品代码**没有**经 SecretPort 读取这几个逻辑名，实际生效的是上表的 Spring 属性。特别是 `NEXUS_KEYCLOAK_CLIENT_SECRET`：只设置它**不会**生效，必须设置 `NEXUS_IAM_KEYCLOAK_CLIENT_SECRET`。
- 主库口令、Keycloak 客户端密钥和引导令牌目前都是以 Spring 属性的形式存在，进程环境里可以看到。部署时注意 §4 中 actuator `info.env` 的暴露面（由 L12 处理）。
- Redis：当前代码**不支持** Redis 口令，只有 `NEXUS_REDIS_HOST`、`NEXUS_REDIS_PORT`。Redis 必须部署在私有网络中，只允许应用访问。

## 2. 运行时由管理员写入的密钥（`platform.secret_ciphertext`）

这些密钥由租户管理员通过 API 写入，用主密钥加密后落库，**不以任何形式出现在环境变量或配置文件里**。

| 逻辑名格式 | 写入入口 | 用途 | 可见性 |
|---|---|---|---|
| `iam.idp.{tenantId}.{providerId}.client-secret` | `PUT /api/v1/identity/providers/{id}/secret`、`POST .../secret/rotate`（N10，需要管理员 + MFA） | 租户 OIDC IdP 的 client secret；测试连接时使用 | 只返回 configured/version；审计只记录版本号 |
| `p5.credential.{tenantId}.{credentialId}` | `/api/v1/p5/credentials/{id}/secret` 写入/轮转（M16–M19） | 集成连接器的凭据 | 同上；撤销时删除密文 |

- **P5 内部 API 客户端密钥**：签发时**只返回一次**，库中只保存 digest（`integration.api_client.secret_digest`），**无法找回**。丢了就重新签发。
- 这两类密钥都依赖 `NEXUS_CRYPTO_MASTER_KEY`。**只备份数据库、不备份主密钥 = 这两类密钥全部不可恢复**（L11 会把这一点写进恢复步骤）。

## 5. 交付和保管要求

1. 每个环境单独生成 `NEXUS_CRYPTO_MASTER_KEY`，长度不低于所用套件的密钥长度（INTERNATIONAL 为 32 字节，hex 编码后 64 个字符；GM 为 16 字节，hex 编码后 32 个字符，可以用更长的主密钥）。和数据库备份**分开保管**，但**恢复时两者都要有**。
2. 引导令牌只在初始化窗口内设置，用完立即清空。
3. 所有密钥都不能进入：仓库、`application*.yaml`、容器镜像层、CI 日志、工单和聊天记录。
4. 轮换密钥后，核对审计里的 `p2.idp.secret.rotated`、`p5.credential.secret.rotated` 等事件。

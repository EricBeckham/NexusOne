## 结论

路径没有走通。P1 之后演示后端能在一次性空库上留住进程，K20 不再因字段 `ON CONFLICT` 退出。断点在目录和订阅：应用目录接口 500，林晓也不是租户管理员，订阅开通被拒绝。发起、审批意见、我的申请结果都没走到。

## 实际做了什么

1. 本机 PostgreSQL 15 在 `127.0.0.1:5432` 监听。`8080` 和 `5173` 空闲。角色 `nexus` 不存在；用 `postgres` 连一次性库 `nexusone_p5`。口令留在本机环境，不写入本文。已有库 `nexusone` 未迁移、未清理。
2. `mvn -DskipTests package` 成功。演示开关打开（`NEXUS_DEMO_ENABLED=true`，`NEXUS_DEMO_ENVIRONMENT=local`），`NEXUS_IAM_IDP=stub`，数据源指向 `nexusone_p5`。身份持久化设为 `jdbc`，并且身份库地址也指向这只一次性库；默认的 `memory` 读不到种子成员。
3. 空库迁完后 Tomcat 监听 `8080`，日志有 `Started NexusOneApplication`，并有「演示开关已打开。禁止连生产。」进程没有再因种子失败退出。
4. 浏览器打开 `http://127.0.0.1:5173/login`。在 stub 登录框填 `lin.xiao@demo.invalid` / 林晓，点「生成 token 并登录」。页面生成的 `sub` 是 `local-lin.xiao@demo.invalid`，不是种子里的 `demo-seed:p2:lin`。因为身份库是 jdbc，登录按邮箱对上了种子账号，签发了种子租户上下文：账号 `…0201`，人员 `…0203`，租户 `…0101`。同时把该账号的 `keycloak_user_id` 改写成了 `local-lin.xiao@demo.invalid`。周然仍是 `demo-seed:p2:zhou`，这次没有登录。
5. 进入应用目录 `/p4/market`。页面显示「加载失败 / Internal error」。`GET /api/v1/p4/catalog` 返回 500。服务端是 `invalid SKU entitlements`：P4 演示种子的 SKU JSON 是 `{"demo":true,"entitlements":{...}}`，读模型要的是 `Map<String, EntitlementSpec>`。整份目录因此列不出来，「演示数据 · 简单审批」没有出现在页面上。
6. 单独 `GET /api/v1/p4/skus/demo.simple-approval` 返回 200，名称是「演示数据 · 标准」。K20 这一条 SKU 本身能读。
7. 用当前林晓会话调用页面同一个订阅接口 `POST /api/v1/p4/tenants/{tenantId}/subscriptions`（SKU `demo.simple-approval`，版本 `…0504`）。响应体仍是 Internal error。日志是 403：`tenant administrator role is required`。订阅要求任职岗位代码为 `TENANT_ADMIN`。种子岗位是林晓「研发经理」`engineering_manager`、周然「软件工程师」`software_engineer`，都不是 `TENANT_ADMIN`。
8. 没有开通记录，所以没有点「发起」，没有填事由和审批人，没有待办同意，也没有回到「我的申请」。
9. 冒烟结束后已停掉后端和 Web，并 `DROP DATABASE nexusone_p5`。

| 这次把身份持久化指到一次性库，并用登录页按钮 | 按邮箱对上林晓，有租户上下文；`sub` 仍是 `local-<email>`，并覆盖了种子里的 `keycloak_user_id` |

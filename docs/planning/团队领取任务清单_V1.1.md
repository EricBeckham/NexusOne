# NexusOne 团队领取任务清单 V1.1

本清单用于把[实施任务拆解](./实施任务拆解_V1.1.md)中的父任务交给不同成员。**当前只拆分、建单和交接；不执行代码、数据库操作、测试或部署。**第一批 23 张 [P0 叶子 Issue（#23～#45）](https://github.com/EricBeckham/NexusOne/issues?q=is%3Aissue+label%3Atype%3Aleaf) 已建立，等待团队负责人领取。每张叶子任务由一名负责人领取，另指定一名跨模块评审人；人数和工期由团队决定。已有 PoC 仅作参考，不自动计为产品验收。

## 执行环境与交接规则

- 数据库：本机 PostgreSQL 15，`localhost:5432`，账号 `postgres`。密码由领取人经本机环境变量或受控 Secret 输入；**不写入 Git、Issue、命令示例或测试报告**。业务开发另建最小权限账号，避免长期使用超级用户。
- 缓存：本机 Redis 3.2，`localhost:6379`。P0-05 先核对该版本的命令、锁和故障恢复能力；既有 Redis 8 候选 PoC 不能直接代表本机版本验收。
- 运行：Java 服务在本机作为 JAR/本机进程运行；本轮禁止 Docker、Compose 和容器依赖。Keycloak、对象存储等非业务 JAR 组件由对应负责人给出本机原生运行方案。Java 21 仍是产品基线；已有 Java 8/17 PoC 需按 Java 21 复验。
- 工作方式：领取 Issue 后填写负责人、评审人、代码目录、依赖 Issue、环境与版本、验收证据链接。一个人可以领取多个无冲突任务，但每项要有明确完成判定。P0 叶子任务优先于 M0 实现；接口设计与测试用例可并行准备。
- 双数据库与信创差异：两份 V1.1 基准文档仍有 GaussDB-only 要求。当前用户指定 PostgreSQL-only 执行，因此仅能报告 PostgreSQL 范围的结果；正式发布门禁另行修订基准口径后认定。

## 第二批：M0 子任务分派建议

M0 的 [#11～#22](https://github.com/EricBeckham/NexusOne/issues?q=is%3Aissue+label%3Aphase%3AM0) 已建父 Issue。先让模块负责人领取并建立接口/验收脚本，再按下表把实现分给成员；相关 P0 门禁未完成前，任务只能做设计和准备。

| 父任务 | 可分给不同成员的子任务 | 主要依赖 |
|---|---|---|
| M0-01 工程底座 | 模块边界与 API/错误码；Java 21 本机 JAR 启动与 PostgreSQL 迁移；日志/Trace/健康 | P0 版本冻结 |
| M0-02 隔离内核 | 请求 TenantContext/PlatformContext；SQL Guard 与 CI；异步/缓存/文件传播 | P0-01 |
| M0-03 P1 | 租户生命周期与平台租户；默认权益投影及应用/台账 Quota | M0-01/02，P2 管理员接口 |
| M0-04 P2 身份 | 人员/全局账号与 Keycloak 对账；部门/岗位/任职及租户切换 | P0-03，M0-02 |
| M0-05 P2 权限 | 授权与 Deny；DataScope/FieldPolicy；PolicySnapshot/Redis 失效 | P0-02，M0-04 |
| M0-06 P3 数据 | 应用/台账/字段元数据；SchemaService/Quota；CRUD/查询/分页 | P0-01/08，M0-03/05 |
| M0-07 P3 发布 | 基础表单；Validate/Publish/Running 与失败回滚 | M0-06 |
| M0-08 流程 | 顺序审批定义与办理人解析；发起/同意/驳回/撤回；待办/已办/我发起 | P0-04，M0-05/07 |
| M0-09 执行通道 | Quartz；Task Queue；Outbox/幂等/重试/对账 | P0-07，M0-02 |
| M0-10 公共服务 | Redis CachePort；文件服务；站内通知 | P0-05/06，M0-09 |
| M0-11 审计与恢复 | 审计采集/哈希链；Crypto/Secret；PostgreSQL 整库与对象恢复演练 | P0-10，业务路径 |
| M0-12 前端与验收 | 租户/组织权限界面；台账/表单/待办界面；双租户与真实业务脚本 | M0-03～11 |

M0 只验收一条真实业务闭环（G18）。完整 S0/S1 发布的 G7 至少三类真实业务，另在父任务计划中追踪。P4、P5、Kafka、OpenSearch、Kubernetes 不进入 M0。

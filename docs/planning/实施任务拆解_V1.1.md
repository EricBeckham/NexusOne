# NexusOne 实施任务拆解 V1.1

依据：《星枢企业业务平台_需求规格_V1.1》§3.1、§10–12；《星枢企业业务平台_技术框架_V1.1》§18–19、§27–29。本文是执行任务板，不修改两份基准文档。**2026-09-22 用户确认：P0 按本机可执行范围收口。** 数据库为 PostgreSQL 15.18，`127.0.0.1:5432`；缓存为本机 Redis 3.2.100，`127.0.0.1:6379`，只测单节点；Java 21 本机进程，不使用 Docker。容量阈值不冻结，本机结果不算目标 Linux/ARM Profile，Keycloak、Flowable、MinIO 本轮不做升级回滚，SAML、LDAP/AD、短信 MFA 本轮不接。密码只经本机环境变量提供，不进入仓库或 Issue。

可直接分配给成员的细粒度任务见[团队领取任务清单_V1.1.md](./团队领取任务清单_V1.1.md)。本文件中的 10 个 P0、12 个 M0 Issue 是父任务，仍用于阶段和验收追踪。

## 1. 优先级与阶段

| 顺序 | 目标 | 退出条件 |
|---|---|---|
| 0 | P0 技术概念验证与版本冻结 | P0-1～P0-10 形成可复现报告、版本/许可证/PostgreSQL 部署 Profile 清单，关键契约测试在 PostgreSQL 上通过 |
| 1 | M0 首期执行切片 | 一条真实业务走通租户→组织权限→台账→表单→发布→数据→顺序审批→待办→查询→站内通知→审计；满足 G18 |
| 2 | S0+S1 基础产品共同发布 | PostgreSQL 范围内适用的门禁通过；G7 至少 **3 类**真实业务闭环。基准文档中的双数据库 G14 暂不能宣称通过 |
| 3 | S2 治理成熟 | 按需求规格 S2 原子需求排期，包含全局搜索等；不把单租户逻辑恢复加入 V1.1 |
| 4 | S3 商业化 / P4 | Product、SKU、Subscription 成为商业权益唯一真相源；共享应用包的前向兼容与对账 |
| 5 | S4 开放生态 / P5 | API Client、Webhook、Connector 等按 S4 门禁交付 |

M0 是 S0/S1 的子集，不是一套新阶段。阶段优先于“核心/标准/高级”成熟度。AI、数字人、Kafka、OpenSearch、APISIX、OpenBao、Kubernetes 均不进入首期任务。

## 5. 发布前必须冻结的决定

- Spring Boot 稳定 GA minor；Query 执行层（jOOQ/MyBatis 候选）；受限表达式实现（Aviator/SpEL 候选）。
- Keycloak、Flowable、Quartz、Flyway 具体版本及 PostgreSQL 支持组合。
- Redis 版本/许可证；MinIO/AIStor 产品线、版本、来源和授权；国密 Provider 来源与资质。
- PostgreSQL 目标 OS、CPU、JDK 与部署方式组合，不做任意排列组合承诺。
- P0-08 的单租户自建台账数、集群物理表数、索引数、Catalog 压力、DDL P95 等阈值；冻结前不承诺无限自建台账。

## 6. 边界与文档一致性记录

- 当前所有任务仅在 PostgreSQL 执行。两份 V1.1 基准文档仍要求 PostgreSQL/GaussDB 双数据库和 GaussDB-only 信创组合，因此本任务板是经用户指定的执行范围调整；G14 的 GaussDB 部分及相关正式基准门禁保持**未验证**，不能标记通过。若最终发布范围也改为 PostgreSQL-only，需要同步修订需求规格和技术框架的验收口径。
- 需求规格 §10.5 和技术框架 §19.6、§28.2 明确 V1.1 **不提供单租户逻辑恢复**，租户导入/导出只用于迁移。技术框架 §27、§32.4 仍残留相关测试/目标字样，执行以 V1.1 明确排除规则为准，留待基准文档修订。
- P4 商业权益从 S3 起为唯一真相源；M0 的 P1 只实现同结构运行态投影和 Quota。
- Keycloak 只管认证/凭据/会话，P2 持有人员组织岗位角色策略主数据；Flowable 只作流程执行，P3 不读其内部表。
- 动态台账 DDL 仅由 SchemaService 管理，Flyway 仅管平台静态表；单租户应用回滚不得回滚共享物理 Schema 或已有业务数据。

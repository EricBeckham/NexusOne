## 3. 演示准备（林晓 `nexus-demo-tenant-admin`，`demo_acme`）

1. [ ] 星构 · 业务类型：确认「费用报销」（台账 `expense`：费用说明、金额、费用类别、收款人、备注）已开通并可提交审批。
2. [ ] 星构 · 台账：新建台账「付款台账」（编码如 `payment`），字段：
   - `payee` 收款人（文本，必填）
   - `amount` 金额（数值，必填）
   - `memo` 备注（文本）
   - `source_no` 来源单号（文本）
   - `pay_status` 付款状态（文本，必填）
   - `decided_at` 审批时间（时间）

   发布为 READY。
3. [ ] 星构 · 流程与自动化 → **办结后动作** → 新建：
   - 名称：报销通过→付款
   - 触发：审批通过
   - 源台账：费用报销；流程：报销审批使用的流程
   - 目标台账：付款台账
   - 映射：`payee` ← 源单字段「收款人」；`amount` ← 源单字段「金额」；`memo` ← 源单字段「费用说明」；`source_no` ← 系统值「来源单号」；`pay_status` ← 固定值「待付款」；`decided_at` ← 系统值「办结时间」
   - 保存成功；把 `amount` 改成来源「费用说明」再保存 → 页面列出类型不匹配问题（验证后改回）。

## 4. 验收

### 4.1 通过即插行

- [ ] 周然 `nexus-demo-member` 提交一张费用报销（金额例如 128.50）。
- [ ] 林晓在待办中**通过**。
- [ ] 数秒内，付款台账出现 1 行：收款人 / 金额 / 备注与报销单一致，来源单号为报销单记录编号，付款状态「待付款」，审批时间为办结时间。
- [ ] 该行的创建人显示为**周然**（发起人）。
- [ ] 办结后动作页「执行记录」：一条「成功」，生成的行编号与付款台账新行一致，尝试 1。
- [ ] 报销单自身的审批状态为「已通过」，与动作执行无关。

### 4.2 驳回不插行

- [ ] 周然再提交一张，林晓**驳回** → 付款台账不新增；执行记录不新增（触发 = 审批通过）。
- [ ] 把动作触发改为「通过或驳回」后再驳回一张 → 付款台账新增一行，执行记录「成功」，审批结果列显示「驳回」；验后改回「审批通过」。

### 4.3 不重复、可重试

- [ ] 同一张单不会产生两行（刷新、重复查看执行记录均不变）。
- [ ] 失败演练（可选，不在演示机改数据）：在测试环境先把付款台账停用或删掉必填映射后再通过一张 → 执行记录「失败」，错误类别为编码（如 `P3.LEDGER.0003`），**审批结果不受影响**；恢复台账后点「重试」→ 变为「成功」，尝试次数 +1，付款台账只多一行。

### 4.4 权限

- [ ] 周然直接打开 `/p3/completion-actions`：提示需租户管理员，接口为 `no_grant`。
- [ ] 平台运营进不了星构（PV），不涉及本功能。

## 5. 异常对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面「办结后动作没有加载」 | jar 不含 FA3，或 SPA 不含 FA5 | 同 SHA 重新打包部署 |
| 林晓打开页面提示需租户管理员 | 其岗位不是 `demo_tenant_admin` / `TENANT_ADMIN`，设计者角色未挂上 | 按 DEMO-U3 核对岗位；让林晓访问任一星构页面触发授权补齐后再试 |
| 通过后付款台账无新行、执行记录也无 | 动作停用 / 源台账或流程不匹配 / 触发条件不符 | 核对动作配置 |
| 执行记录「失败」 | 目标台账不可用、字段校验失败等（看错误类别） | 修正后在执行记录中重试 |
| 执行记录一直「执行中」 | outbox 调度未运行 | 查看应用日志中 outbox 调度状态；不在演示机改开关，按运维流程处理 |

## 错误明细（16）— 本波回归

受影响的类（均位于 `nexus-p3-studio/src/test/java/one/nexus/p3/path/`）：`G18BusinessPathIT`(4)、`G2SubmitStartFormWriteIT`(3)、`G7BusinessTypesIT`(3)、`G7ExpenseTravelQueryIT`(2)、`G7ExpenseTravelWithdrawIT`(2)、`G7LeaveWithdrawIT`(1)、`G7WithdrawWalkthroughIT`(1)。

**根因**：Spring 上下文启动失败（14 次 `NoSuchBeanDefinitionException`，其余是上下文失败缓存后的 `IllegalStateException`）。
- `PinnedProductApplicationValidationService`（K15a）是组件扫描进来的 `@Service`，带 `@ConditionalOnBean({IdentityRepository, FileObjectRepository})`。
- 测试上下文 `G18PathApplication` 不扫描 `one.nexus.file`，没有 `FileObjectRepository`，因此这个 bean 被跳过。
- `ProductApplicationService` / `ProductApplicationController`（K15b）却无条件依赖它，结果整个上下文起不来。
- 生产引导 `nexus-bootstrap` 的 90 个测试全绿，说明产品装配路径正常；坏的只是 P3 自带的测试上下文。
- 在 K0e 之前的 main（`5f045d6e`）上把 K0e 改动 stash 后可以复现，**不是 K0e 引入的**。

**处理建议**：单独开一张小卡。可选做法：让 Service/Controller 使用同样的条件，在 `G18PathApplication` 里补齐 file 相关 bean，或者去掉组件上的 `@ConditionalOnBean`（它依赖注册顺序，比较脆弱）。验收标准：上述 16 个测试转绿，且 bootstrap 装配不回归。这个修复已作为独立任务提出，不在 L1 范围内。

# PV5 · 三类用户产品范围：合入顺序与验收

规则见 [PV1](PV1-三类用户产品可见性与权限规划.md)。本文只写流程与勾选项，不代表已部署或已验收。演示机不热修，不改 `NEXUS_*` env；网络面板只确认请求与字段存在，不记录 token、context id、person id 原值。

## 1. 合入顺序

| 顺序 | 卡 | PR | 内容 |
|---|---|---|---|
| 1 | PV1 | #752 | 规划（docs） |
| 2 | PV2 | #753 | 后端 `GET /api/v1/auth/products` |
| 3 | PV3 | #754 | 前端：切换器 / 产品选择页按可见产品渲染；单产品直达；无权访问页 |
| 4 | PV4 | #755 | 后端：`tenant_member` 收回流程设计写权限，租户管理员经 `tenant_process_designer` 获得 |
| 5 | PV5 | 本卡 | 验收（docs），并更新 DEMO-U7 |

五张均以 `main` 为基，互不叠加。PV3 单独部署时，旧后端回 404，切换器保持五项（不锁人）；需与 PV2 一起部署才生效。

## 3. 验收（硬刷新，各人独立会话）

### 平台运营 `nexus-demo-platform`

- [ ] 登录后产品选择页 / 切换器只有 **星域、星权、星市**。
- [ ] 网络面板：`GET /api/v1/auth/products` 返回 200，`products` 为 `p1、p2、p4`。
- [ ] 直接打开 `/p3`：显示「无权访问该产品」。
- [ ] 星域租户目录、星市产品定义照常可用（AUTH6 系列）。

### 租户管理员 林晓 `nexus-demo-tenant-admin`

- [ ] 产品只有 **星权、星构、星市**；若 `demo_acme` 权益投影开通了 `connect`，另有星联；未开通时不出现星联（预期）。
- [ ] 直接打开 `/p1/tenants`：显示「无权访问该产品」；服务端仍拒绝。
- [ ] 流程设计（保存 / 校验 / 发布流程定义）可用（PV4 `tenant_process_designer`）。
- [ ] 报表导出成功（DEMO-U5，不受本波影响）。

### 一般用户 周然 `nexus-demo-member`

- [ ] 登录后**直接进入星构工作台**（`/p3`），不经过产品选择页，侧栏没有产品切换。
- [ ] 待办、我的申请、通知、日常台账 / 填表提交可用。
- [ ] 直接打开 `/p1/…`、`/p2/…`、`/p4`、`/p5`：显示「无权访问该产品」，只提供「进入星构」。
- [ ] 保存 / 发布流程定义被服务端拒绝（`no_grant`）；导出、组织管理仍为 `no_grant`（DEMO-U5）。

### 切换租户（若同一账号有多个 ACTIVE 成员资格）

- [ ] 在用户菜单切换租户后，切换器随新租户的范围刷新。

## 4. 异常对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有人仍看到五个产品 | SPA 不含 PV3，或后端不含 PV2（`/api/v1/auth/products` 404 → 前端按未知处理） | 同 SHA 重新打包部署 |
| 周然仍能保存流程定义 | jar 不含 PV4，或周然尚未在新 jar 上发起过请求 | 部署后让周然访问任一工作台页面再复验 |
| 林晓无法设计流程 | 其任职岗位不是 `demo_tenant_admin` / `TENANT_ADMIN`，或未 ACTIVE | 按 DEMO-U3 核对岗位 |
| 平台运营产品为空 | 平台职责未指派 | 按 DEMO-U2 / TC5 §0.1 核对 |

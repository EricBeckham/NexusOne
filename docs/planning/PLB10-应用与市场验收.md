## 1. 分类与清单（PL2）

- [ ] 平台模式打开应用包页，能新建、修改、删除分类，并把分类指定到当前应用。正在使用的分类删除被拒绝。
- [ ] 选择草稿版本，编辑清单后点校验：多个问题同时列出（路径和原因码都在），不在第一个问题处停下。
- [ ] 草稿可以保存；已发布版本不能改清单。
- [ ] 清单里的应用编码、版本号、分类与当前应用不一致时，问题里出现 `app_code_mismatch`、`version_mismatch` 或 `category_mismatch`。

## 2. 产品与上架（PL3）

- [ ] 产品可以挂多个已发布应用版本，SKU 的 `app_id` 为空、`product_id` 有值。
- [ ] 已发布产品可以下架。下架后 `GET /api/v1/p4/catalog/groups` 不再出现该产品。重新上架后回到原分类。
- [ ] 应用目录在有分类数据时按分类展示产品货架。申请开通不带版本号。
- [ ] 草稿产品、以及只挂在应用上的旧 SKU，不出现在分类货架里。原有 `GET /api/v1/p4/catalog` 仍返回已发布应用版本。

## 3. 订购与实例（PL4）

- [ ] 租户订购产品型 SKU 后，产品里的每个应用都有 `INHERIT` 实例，版本和入口来自清单。
- [ ] 角色包落到租户角色，编码形如 `app_leave_leave_applicant`。角色没有被自动绑到岗位。
- [ ] 租户自助路径发出 `p4.app_instance` 事件，且带 `previous_version` 为空时种类是安装。平台批准路径不发这条事件。
- [ ] 同一主版本有更新时，已开通页给出升级提示。确认升级后实例版本前进、`revision` 加一；角色包新增的授权补上，清单里删掉的授权仍留在租户侧并在结果里列出。
- [ ] 卸载后实例行还在，状态为 `UNINSTALLED`，入口为空。该产品没有仍在安装中的实例时，订阅变为取消。
- [ ] 产品打开「小版本自动升级」后，同一主版本的新发布会追上复用实例，且不发租户事件。主版本号变化仍要手动升级。派生（FORK）实例不能走这条升级。

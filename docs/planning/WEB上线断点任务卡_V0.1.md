## 卡片正文

### H1 — SKU → product definition 关联（阻塞订阅）

**现象**（G5）：`MarketService.subscribeProduct` 返回 `404 catalog SKU has no product definition`。目录可见演示产品，订阅失败。

**要求**：

- 查清演示 SKU（简单审批）与 `market.product_definition` / `market.sku_product_binding`（或当前等价表）的关联为何缺失或未生效；只改种子 / 绑定 / 订阅所需最小面。
- 本地空库 + demo 开关：订阅开通演示 SKU 成功。
- 加回归测试（种子或服务层），防止再出现「目录有 SKU、订阅无 definition」。
- **禁止** `outOfOrder=true`；若需新迁移，版本号取全局最高已用版本 +1（V705 规则不变）。
- 一卡一 PR；不扩发起页 UI、不改无关产品。

### H2 — 目录 SKU 结构对齐（阻塞正确订阅请求）

**现象**（G5）：按钮文案 `订阅开通 undefined`，摘要像只有数量 `1`，怀疑目录 DTO / 序列化与前端字段不一致，导致请求可能带上错误或空的 `sku_code`。

**要求**：

- 核对 `GET` 目录（catalog）响应中 SKU 的 JSON 形状，保证前端能读到稳定的 `code`、`name`（若需嵌套，在 API 合同或适配层写清并保证可订阅）。
- 订阅请求必须带上真实 `sku_code`；可用契约测试或 HTTP 测试锁定形状。
- 一卡一 PR；优先后端合同修正；若纯属前端读错字段则与 H5 分工说明，避免两人改同一处打架。

### H3 — 订阅错误可读 + 否定用例

**要求**：

- 缺 product definition、非租户管理员、重复订阅等路径返回明确业务错误（勿吞成无信息 Internal error）。
- 补否定用例；不扩成功路径范围。
- 一卡一 PR。

### H4 — 已开通 → 发起后端最小通路

**前置**：H1 已合（订阅能成功）。

**要求**：

- 订阅成功后，演示产品安装钉 / 发起相关后端接口对「演示数据 · 简单审批」可用（林晓能发起）。
- 只做阻塞发起的最小后端面；前端发起页大改归 Claude。
- 一卡一 PR。

### H5 — 目录 SKU 展示与按钮文案

# PLX2 · 新模型演示路径

平台建应用 → 上架 → 租户订购 → 管理员把角色绑到岗位 → 成员按入口办理。本文是剧本，不是真机验收。演示机不热修，不改 `NEXUS_*`，不把 `nexus.permission.member-access` 改成 `position`，不记录口令或 token。

Keycloak 三人（平台运营、林晓、周然）的导出和平台只读列表仍走 [DEMO-U](DEMO-U-三人演示路径与操作说明.md)。那三个人和下面这三个人不是同一套账号。

## 1. 数据什么时候出现

只有本机回环数据库，并且部署配置里 `nexus.demo.enabled` 本来就是 `true` 时，启动才会写入。生产环境和演示机保持关闭。关闭时启动什么都不写。

启动顺序固定在 `Plx2DemoSeedOrder`：

1. 演示租户 `01900000-0000-7000-8000-000000000101`。
2. PLA8：部门 `pl_office`，岗位 `tenant_admin` / `pl_lead` / `pl_member`，人员陈管理、周审批、林办理，以及岗位角色。
3. PLB9：分类 `oa`、请假应用清单 `1.0.0`、已发布产品 `pl_leave`、产品型 SKU，演示租户订购，并把落地后的角色补到岗位上。申请人角色在 `pl_member`，审批人角色在 `pl_lead`。两边都还留着 `tenant_member`。
4. 门户菜单和首页模块留给 PLC9，顺序号 `1200`，必须排在上面这步之后。#799 还没合入，所以这一步现在不会写菜单。

再启动一次不会多出第二份组织、订阅或实例。

## 2. 三个人

| 人 | 工号 | 岗位 | 办理什么 |
|---|---|---|---|
| 陈管理 | `E-PL-ADMIN` | `tenant_admin` | 看组织、岗位角色和有效权限。流程设计角色在这个岗位上 |
| 周审批 | `E-PL-LEAD` | `pl_lead` | 审批请假。角色 `app_leave_leave_approver` |
| 林办理 | `E-PL-MEMBER` | `pl_member` | 填写请假。角色 `app_leave_leave_applicant` |

## 3. 操作

1. 用已合入 `main` 的构建。本机演示开关按第 1 节。演示机不要为了这条路径把开关打开。
2. 平台侧确认应用目录里「办公」分类下有「请假」，SKU `pl_leave` 已上架。这是种子写好的，不要在演示机手工插表。
3. 陈管理进入岗位页：`pl_member` 上有成员角色和请假申请人，`pl_lead` 上有成员角色和请假审批人。打开两人的有效权限预览，来源是岗位。
4. 林办理打开星构里已安装的请假入口（键 `fn:leave:leave_apply`）提交一条请假。周审批在待办里办理。
5. 门户 `/portal` 要等 PLC9 合入并重新部署后，才按「菜单 ∩ 可读入口」演示。在那之前，成员从星构功能入口进入，不把门户菜单说成已经配好。

## 4. 不要做的事

- 不在演示机打开 `nexus.demo.enabled`，不改权限兼容开关，不手改市场表或权限表。
- 不把林晓、周然说成陈管理、林办理。
- 不演示基线差异和手动合并（PLC8 还没有）。
- 门户配置页（PLC4，#798）和门户种子（PLC9，#799）未合入前，不勾「菜单已分组、首页模块已写入」。

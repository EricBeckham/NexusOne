# 快进 P4/P5 范围冻结表 V0.1

> **文档状态**：**确定**（Eric 2026-09-23 批准确认）
> **依据**：《需求规格 V1.1》《技术框架 V1.1》、WEB/H5 设计规范 V1.1（已确定）  
> **目的**：在「尽快摸到 P4 星市 / P5 星联」前提下，冻结哪些做、哪些暂缓、哪些明确不做，作为排期合同。  
> **裁剪规则（规格原文）**：阶段决定排期；同阶段内 **核心不可裁**，**标准可按版本裁**，**高级只在明确场景交付**。

## 0. 快进策略一句话

**先做薄 S0+S1 核心闭环（P1–P3）→ 跳过/后置几乎全部 S2 → 上薄 P4（S3 核心）→ 再上薄 P5（S4 核心）。**  
S3 之前继续用**平台预置默认权益包**；切到 P4 订阅后再把商业真相源交给星市。

### 0.1 第一期落地优先级（Eric 2026-09-23）

| 优先 | 内容 | 说明 |
|---|---|---|
| **第一期先做** | **自己用户登录**（NexusOne 终端用户 / 租户用户经 Keycloak 的认证与会话） | 能开户后的账号登录、保会话、进五产品壳；与账号人员主数据最小面一起闭环 |
| **整包后置** | **开发者门户**、**外部 OAuth 生态**（第三方应用注册/审核、外部客户端凭证自助、合作伙伴开放平台） | 不进第一期，也不挡「自己用户登录」关门；归 P5 开放平台后期包 |

第一期**不**把对内 API / Webhook / 连接器当门禁；那些仍属后续薄 P5（自用）排期。

### 0.2 正向主路径优先（Eric 2026-09-23）

**所有备份、恢复相关工作整包后置**（含整库备份、单租户恢复、RecoveryPort 真恢复、产品级 HA/RPO 宣称）。
本波次只把 **正向一条路** 走通：登录 →（后续）租户/权限/一单业务 → 再薄 P4/自用 P5；不以备份恢复为门禁或并行车道。
UI 约束：从本冻结生效起，新页面必须按已确定的 WEB/H5 规范与五产品壳落地，不再扩验收壳/leftover 主入口。

## 2. 可暂缓（Defer）— 不挡「先摸到 P4/P5」

### 2.1 整阶段后置

| 范围 | 处理 |
|---|---|
| **P1–P3 几乎全部 S2**（治理、迁移、代管、高级搜索过滤、规则引擎产品化、流程运维高级等） | 整体后置于薄 P4 之后或并行小队 |
| **P4 全部 S4**（灰度版/测试版渠道等） | 薄 P4 之后 |
| **P5 标准/高级大部** + **第三方开放平台**（外部开发者门户、第三方 OAuth 客户端生态、应用市场/上架审核、合作伙伴入驻、公开文档站做全、企业级开放治理等） | 薄 P5 **自用**骨架之后；开放平台整包后期 |
| S0+S1 中标注为 **标准** 的约 291 项 | 按版本裁进 S1.x，不挡关门 |

### 2.2 模块级暂缓清单（优先扔到后面）

**P1**：4.3 品牌细项、4.7 平台内容运营、4.8 租户关系扩展、销毁证明/物理迁移/代管（本就偏 S2）  
**P2**：5.6 有限条件策略配置界面（规格已标 S2 配置面）、5.8 权限治理报表、5.10 企业身份集成细项、5.11 人员生命周期边角、5.12 个人中心大而全  
**P3**：6.9 规则引擎产品化、6.10 决策表、6.11 跨台账编排、6.12 页面构建完整度、6.13 报表与 BI、6.14 数据治理、6.15 全局搜索、6.16 门户花活、6.17 协作、6.18/6.19 完整发布治理与运行治理  
**P4**：7.7 Overlay、7.9 价格优惠、7.11–7.15 计量/账单/支付/发票/商业运营（先人工开通订阅 + 预置/手工权益）  
**P5**：第三方开放平台整包；8.4–8.9 各类连接器大全；外部开发者门户 / 第三方应用审核与上架；合作伙伴入驻；公开文档站做全；扩展与治理增强  

### 2.3 工程侧暂缓

| 项 | 处理 |
|---|---|
| honesty / leftover / harness 清零 | 不作为进 P4 门禁；保持诚实标记即可 |
| 活环境/信创/ARM Profile 穷举 | 只保冻结 Profile |
| **全部备份 / 恢复**（整库备份、单租户逻辑恢复、RecoveryPort 真恢复、产品级 HA / 分钟级 RPO） | **整包后期**；本波次不排期、不做门禁；已有 dry-run/诚实标记可保留但不加码 |

## 3. 明确不做（Out）— 本快进波次声明不做

与规格 M0/排除项对齐，本波次**不排期、不验收为产品能力**：

- 全局搜索、完整 BI/报表产品化  
- Kafka / OpenSearch / 独立 API Gateway / Kubernetes 强依赖  
- 单租户逻辑恢复、隔离模式升级为独立库集群（作为主路径）  
- 高级 ABAC；会签/或签/加签/减签/流程迁移  
- 邮件/短信**业务**通知（Keycloak SMTP 仅部署需要可配）  
- 信创组合穷举；等保/密码机/通算全量交付宣称  
- 把 leftover 诚实页当五产品正式 IA
- **第三方开放平台**（外部开发者生态）——星联本波仅自用，开放平台整包后期
- **备份、恢复整包**（含整库/单租户/RecoveryPort 真恢复）——先正向主路径，全部后期

## 4. 关门定义（便于验收争论时引用）

| 里程碑 | 定义 |
|---|---|
| **第一期关门（登录）** | 租户用户可用自己账号登录、会话保持、进入产品壳；**不含**开发者门户 / 外部 OAuth |
| **M0 产品关门** | 浏览器真闭环 + P1–P3 按设计规范分产品壳；非 JSON 验收壳 |
| **可进薄 P4** | 上表 1.1–1.4 Must 达到「可演示开通租户并跑通一单审批」；预置权益投影可写 |
| **薄 P4 关门** | 应用可发布安装 + 订阅能驱动权益投影；P4 壳符合规范 |
| **薄 P5 关门（自用）** | **内部**系统能按范围调通 API + 自有 Webhook 投递 + 1 个自用连接器样例；P5 壳符合规范；**不**要求第三方可自助接入 |

## 实际做了什么

1. 本机 PostgreSQL 15 在 `127.0.0.1:5432` 监听。`8080` 和 `5173` 空闲。角色 `nexus` 不存在；按 runbook 用 `postgres` 连上。口令留在本机环境，不写入本文。
2. 已有库 `nexusone` 的 Flyway 成功版本是：`001,002,003,100,101,200,300,400,500,501,510,520,530,531,550,502,503,504,511`。最高版本号是 550，但 502–511 排在它后面。低于 550 且未应用的至少有 `004,005,006,102,201,202`；550 之后的 `551,552,600,601,700–705` 也都没有。当前配置 `outOfOrder=false`，不能拿这份库启动。未对它做迁移或清理。
3. 另建一次性库 `nexusone_l4`。`mvn -DskipTests package` 成功。演示开关打开（`NEXUS_DEMO_ENABLED=true`，`NEXUS_DEMO_ENVIRONMENT=local`），`NEXUS_IAM_IDP=stub`，数据源指向该库。
4. 空库按序迁过 V001–V705。日志有 Tomcat `8080` 和 `Started NexusOneApplication`。随后 K20 的 `ApplicationRunner` 失败，Spring 报 `Application run failed`，进程退出码 1。
5. 失败语句是 `ApprovalProductDemoSeedConfiguration` 插入 `platform.form_template_field` 时的 `ON CONFLICT (template_id, field_key)`。PostgreSQL：`没有匹配 ON CONFLICT 说明的唯一或者排除约束`。
6. 原因：`V005__platform_form_template.sql` 建了 `form_template_field_key_unique (template_id, field_key)`；`V006__allow_invalid_form_template_drafts.sql` 为了让草稿能留下校验错误，把这个约束删了。种子仍按已删除的键做冲突更新。
7. Web 没有启动，浏览器没有打开。订阅、发起、审批意见、我的申请结果都没走到。
8. 冒烟结束后已 `DROP DATABASE nexusone_l4`。
